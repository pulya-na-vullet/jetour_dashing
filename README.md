# Jetour Dashing — инвентаризация ГУ

Сборщик логов штатных камер / 360 / USB на головном устройстве. Только чтение: `dumpsys`, `getprop`, список пакетов, узлы `/dev`. Прошивку не патчит, root не ставит, ключи не вытаскивает.

Коды инженерного меню на ГУ вводите сами. Скрипт начинает работу, когда `adb devices` показывает `device`.

## Зачем

Нужна база до любых экспериментов с APK-регистратором:

1. Видны ли камеры в Android Camera2 (`cameraId`).
2. Кто их держит, когда открыт штатный 360.
3. Забирает ли поворотник / задняя передача exclusive lock.
4. Есть ли USB-том под флешку регистратора.

По вердикту в `report.md` видно, имеет ли смысл писать APK или сразу ставить скрытый DVR.

## Что нужно на ноутбуке

- Python 3.9+
- [ADB platform-tools](https://developer.android.com/tools/releases/platform-tools)
- Кабель USB-A — USB-A
- На ГУ: USB Device (не Host)

Windows: `collect.bat`  
Linux/macOS: `./collect.sh`

## Как снять лог в машине

1. Заведите авто, ГУ должно загрузиться.
2. Приложение «Телефон» → код (сами, скрипт это не набирает):
   - Android 9: `*#20201030#*` или `*#20220730#*`
   - другой распространённый: `*621317658#`
3. USB → Device → OK, выйти на рабочий стол.
4. Кабель в порт ГУ (часто под подлокотником, иногда со значком видео).
5. На ноутбуке:

```bash
python collect.py
```

6. Enter, когда `adb devices` видит машину.
7. Скрипт снимет baseline, затем будет просить сменить картинку на ГУ:
   - **IDLE** — 360 выкл, не задняя, поворотники выкл
   - **360 открыт** — штатный круговой обзор на экране
   - **задняя передача**
   - **поворотник влево**
   - **поворотник вправо**

Каждый раз Enter, когда экран уже в нужном состоянии. Не переключайте картинку, пока идёт съём.

Готово: `logs/hu_diag_ГГГГММДД_ЧЧММСС/`

| Файл | Смысл |
|---|---|
| `report.md` | Вердикт человеческим языком |
| `report.json` | То же для разбора |
| `01_baseline/` | getprop, пакеты, USB, `/dev` |
| `02_idle` … `06_turn_right` | dumpsys камер и foreground на каждом этапе |
| `collect.log` | Что снялось, с кодами возврата |

Если ADB уже подключён и устройств одно:

```bash
python collect.py --skip-wait
```

Несколько устройств: `--serial SERIAL`.

## Вердикты

| Код | Значение |
|---|---|
| `NO_CAMERA2` | Обычный APK камеры не видит. 360 сидит на AVM/оверлее. Регистратор из штатных камер через Camera2 не сделать. |
| `EXCLUSIVE_LOCK` | Камеры видны, но 360/поворотник их забирает. Параллельная запись будет рваться. |
| `CAMERA2_SHARED_OR_IDLE_ONLY` | Камеры видны, на снятых этапах явной драки нет. Можно отдельно пробовать тестовое открытие тех же `cameraId`. |
| `NO_SNAPSHOTS` | Этапы не сняты. |

Скрытый DVR в штатное место у датчика света всё равно самый надёжный бытовой вариант.

## Команды вручную

Если хотите гонять `adb shell` сами:

```bash
python collect.py --print-commands
```

Сложите выводы в ту же структуру папок и разберите:

```bash
python collect.py --analyze logs/hu_diag_...
```

## Проверка инструмента без машины

```bash
python collect.py --demo
python -m unittest discover -s tests -v
```

Demo имитирует типичный Dashing: 0 Camera2, пакет AVM на экране при 360. Вердикт должен быть `NO_CAMERA2`.

## Чего здесь нет

Нет распаковки прошивки, патча HAL, обхода exclusive lock, root, снятия `/data/data`. Это инвентаризация, чтобы не гадать вслепую.
